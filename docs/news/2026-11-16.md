# Barkpark Studio · Monday 16 November 2026

Seven pull requests merged. Four changed what an editor sees: bulk actions, array tools, and three closing ways a read-only view could still write. Two changed only tests, and one started this News.

## What a person can now do

**Act on many rows at once** ([#1266](https://github.com/FRIKKern/barkpark-studio/pull/1266)). Sanity has no bulk actions; this one is Barkpark's own.

1. In a document list, tick several rows. The bulk bar shows **Duplicate selected**, **Discard changes** and **Delete selected**.
2. Press **Delete selected**. The dialog names the count ("Delete 3 documents?") and lists every row it will leave alone, with the reason. A row other documents refer to is listed with those documents, and the button says how many will really go ("Delete 2 documents").
3. It runs one row at a time: "Deleting 2 of 3…". **Stop after this one** stops after the current row.
4. The result lists each row: deleted, duplicated (with a link to the copy), changes discarded, left alone and why, or failed with the error. **Retry n** reruns only the failed or stopped rows. Deleted rows get a **Restore** link. Rows left alone stay ticked.

A Viewer gets no ticks. A Contributor's delete takes drafts only. These roles were checked by simulating them in the page, not with a real seat.

**Arrays** ([#1263](https://github.com/FRIKKern/barkpark-studio/pull/1263)), built from Sanity's 6.17 source.

- An array with several member types opens an insert menu with a search box past 5 types (Enter adds the first match), tabs from `options.insertMenu.groups`, and, with `views: [list, grid]`, a list or grid toggle.
- A long array folds after 4 items (8 in a grid): **Show all N items**. `options.collapseItemsAfter` sets the number; `false` never folds.
- The item dialog has a sidebar tree of every item, with the items of arrays inside them. Search it, pick one, and the dialog, breadcrumbs and URL follow.

**Read-only means read-only** ([#1268](https://github.com/FRIKKern/barkpark-studio/pull/1268), [#1269](https://github.com/FRIKKern/barkpark-studio/pull/1269)). Open a past revision from History, or a scheduled document. Before, typing on the Freeform canvas (a note's whole-document editor) or **Paste document** in the document menu changed the draft, and in a revision so did Cmd+Z. Now a revision opens in the Classic form, the canvas is read-only, Paste document is off, and undo leaves the draft alone. Edits kept on this computer wait until you leave the revision or press **Pause to edit**.

## Where it is slow or rough

- Bulk delete: when a second browser added a reference after the dialog opened, the dialog still said "Delete 3 documents" 2 s later. The check right before the delete held the row back, so nothing referenced was deleted ([#1266](https://github.com/FRIKKern/barkpark-studio/pull/1266)).
- Each bulk row costs about 2 reads from Barkpark, 3 for a Contributor's delete or a discard ([#1266](https://github.com/FRIKKern/barkpark-studio/pull/1266)).
- The lock took three pull requests because each review found more ways round it. [#1269](https://github.com/FRIKKern/barkpark-studio/pull/1269) moved the check to the two places where form and canvas edits are written, instead of one guard per button.
- None of the array screens was compared side by side with a running Sanity Studio; they were built from Sanity's source ([#1263](https://github.com/FRIKKern/barkpark-studio/pull/1263)).

## Across the projects

Bulk delete never forces a delete, so Barkpark's own refusal of a referenced document is the last of its three checks. The same day Barkpark made a refused file (media) delete name only the documents you can read ([FRIKKern/barkpark#26560](https://github.com/FRIKKern/barkpark/pull/26560)); the document delete refusal that bulk delete relies on was not part of that change.
