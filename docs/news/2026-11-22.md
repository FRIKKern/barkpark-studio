# Barkpark Studio · Sunday 22 November 2026

Eight pull requests merged. Seven change what the Studio checks before a publish: five find problems inside items that went unchecked before, and two hold a publish where the Studio could not be sure. One was Saturday's News ([#1385](https://github.com/FRIKKern/barkpark-studio/pull/1385)).

## What a person can now do

**A page builder's items are checked** ([#1379](https://github.com/FRIKKern/barkpark-studio/pull/1379)). A page builder is an array whose `of` lists several member types.

1. Give such an array an item of type `sitat` with an empty required `tekst`.
2. The Studio flags it before any save, titled "Innhold / Sitat / Tekst", and a click in the Validation list jumps to the item. Publish and Publish selected hold.
3. The same rules a one-member array's items get now run inside each item: required, lengths and counts, `unique`, `regex`, URL and email shapes, a value outside `options.list`, and strong references. An item whose `_type` names no member is not judged and never throws.

**References inside items must be published** ([#1381](https://github.com/FRIKKern/barkpark-studio/pull/1381), [#1383](https://github.com/FRIKKern/barkpark-studio/pull/1383)). A strong reference inside an object or an array item, or one that is an item of an array of references, now must point at a published document, as in Sanity. If it points at a draft-only or missing document, the pane's Publish and Publish selected both hold with "Referenced document must be published", and the filled row gets its own mark. A target that cannot be read holds Publish selected with "A document it refers to could not be read: open it to check". A weak reference is never judged.

**minWidth inside rich text** ([#1378](https://github.com/FRIKKern/barkpark-studio/pull/1378)). An image in a rich-text block, at any depth, gets the `options.minWidth` warning. It sits on the text field, and its row names the block and the image field, such as "Innhold / Bilde / Bilder". It stays a warning and never holds a publish.

**The array label lights** ([#1384](https://github.com/FRIKKern/barkpark-studio/pull/1384)). An array field's label now shows the mark when any item under it has a problem, at the worst level: a reference array, a page builder or a plain array.

**A slug check that cannot be answered holds** ([#1380](https://github.com/FRIKKern/barkpark-studio/pull/1380)). When Barkpark refuses the slug query, Publish and Publish selected hold the draft and say the field's name, then "Slug could not be checked. Try again." (nb: «Slug kunne ikke sjekkes. Prøv igjen.»). Before, a refused query read as "not taken" and the publish went through.

**Publish selected judges what it publishes** ([#1382](https://github.com/FRIKKern/barkpark-studio/pull/1382)). Each draft is read again just before it is published. If another editor changed it since it was judged, it is judged again on what Barkpark holds now, at most 2 more times, then held with "It changed while it was checked: open it to check". The reads skip the server's 0.5 s shared cache, so an edit in that half second is seen.

## Where it is slow or rough

- Pages that publish today may now be held. Run over a real site's 171 documents, #1379 gave 2 published pages 3 new errors, each a card text over its 400-character limit; those pages cannot be published until the texts are shortened or the limit raised ([#1379](https://github.com/FRIKKern/barkpark-studio/pull/1379)). The same site would have 0 documents newly held by #1383, but only because it had no drafts at the time ([#1383](https://github.com/FRIKKern/barkpark-studio/pull/1383)).
- Publish selected now reads each draft twice. For 100 drafts that is about 501 requests against about 301 before: some 1.7 minutes of one token's budget of 300 a minute, against 1.0 ([#1382](https://github.com/FRIKKern/barkpark-studio/pull/1382)).
- A short window is left between the footer's last read and the publish. Closing it needs Barkpark's publish to take the revision the Studio saw ([#1382](https://github.com/FRIKKern/barkpark-studio/pull/1382)).
- References in rich text are not judged yet ([#1381](https://github.com/FRIKKern/barkpark-studio/pull/1381)). Cross-field rules do not run inside items ([#1379](https://github.com/FRIKKern/barkpark-studio/pull/1379)).

## Across the projects

The Studio is the editor Barkpark's desk is being rebuilt to match. The same day Barkpark merged 43 PRs; 13 of them went to two people editing one document in the desk, following the Studio's own rules for it ([FRIKKern/barkpark#28176](https://github.com/FRIKKern/barkpark/pull/28176), [#28331](https://github.com/FRIKKern/barkpark/pull/28331)). Barkpark already judges the page-builder cases on its side and sends them back as findings after a save; with #1379 the Studio flags them first, and a Barkpark finding on the same place is shown once.
