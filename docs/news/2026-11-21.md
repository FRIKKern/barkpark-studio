# Barkpark Studio · Saturday 21 November 2026

Twenty-eight pull requests merged. Sixteen change what an editor or a schema author gets: seven for new schema options, three for cross-field rules, five for saving and publishing, and one for the image and file inputs. Ten are end-to-end test work, one tidies the slug option's test and docs, and one was the previous day's News ([#1347](https://github.com/FRIKKern/barkpark-studio/pull/1347)).

## What a person can now do

**Number lists as radios** ([#1346](https://github.com/FRIKKern/barkpark-studio/pull/1346), [#1365](https://github.com/FRIKKern/barkpark-studio/pull/1365)). As Sanity's number `options.list`.

1. Give an `integer`, `number` or `float` field `"options": {"list": [3, 6]}` and `"layout": "radio"`. It draws radios; without the layout, a dropdown. The list takes the same shapes as a string select's, `{value, title}` pairs included.
2. Click 6. The number 6 is stored, never the text "6"; 0 and 0.5 stay themselves. Clear sends an unset.
3. An entry that is not a number of the field's type, such as the string "3", or 0.5 on an integer, is drawn disabled with a note to fix the schema. It is never coerced.
4. A stored value no longer in the list checks no radio and stays as it is. The field says, in Sanity's words, `Value "4" did not match any allowed values`, and Publish is blocked until a value from the list is picked or the field is cleared. Edits still save as a draft. This holds for string selects too, as in Sanity.
5. On a field the editor cannot change here (read-only or hidden for this document, or inside such an object), the same value is only a warning, and Publish stays open. Sanity keeps it an error. A later merge the same day widens this to a field that a role rule in the studio config makes read-only or hidden, for the person it shuts; for anyone it leaves open, it stays an error ([#1365](https://github.com/FRIKKern/barkpark-studio/pull/1365)). Until Barkpark has said who you are, such a field warns. The studio's default config sets no role rule.

**New documents dated today** ([#1339](https://github.com/FRIKKern/barkpark-studio/pull/1339)). As Sanity's `initialValue: () => new Date()`.

1. In a type's `initialValues`, a desk list's or a studio.config template, set a date field to `"$today"`, for example `{"publisert": "$today"}`.
2. Make a new document. The field holds today's date (`YYYY-MM-DD`) in the workspace's time zone, or in UTC when the workspace has none, as Barkpark gives it.
3. When the zone cannot be read (a failed read, no answer within 2 s, or offline), the studio does not guess. The type's own `$today` fields are left for Barkpark to fill in its zone; a desk list's or a template's read UTC.
4. Duplicate keeps its copy as it is, and text typed as `$today` in a reference field's Create stays text.

**A fixed set of documents** ([#1367](https://github.com/FRIKKern/barkpark-studio/pull/1367), [#1374](https://github.com/FRIKKern/barkpark-studio/pull/1374)). Barkpark's schema key `fixedDocuments` lists a type's document ids. Barkpark refuses a new document of the type outside that list, and the delete of a listed one.

1. Add `"fixedDocuments": ["side-om-oss", …]` to a type.
2. The + menu, the list's +, a reference field's create and the incoming-references Add item offer no new document of the type. A create link says why.
3. Duplicate is gone from the document menu and the bulk bar. Delete of a listed id is gone from the document menu, Ctrl+Alt+D and the bulk bar. A document of the type from before the list can still be deleted, as on the server.
4. Opening, editing, publishing, unpublishing and discarding are unchanged. A refusal names the type in plain words, in Norwegian too.
5. Since a later merge the same day, a listed id with no document yet shows as a row, "Not created yet", with its id, after the type's documents ([#1374](https://github.com/FRIKKern/barkpark-studio/pull/1374)). It shows only on the whole plain list (no filter, search, tree, further pages or Published view), and only to someone who may create. Opening it writes nothing, except on a type whose editor builds the document at once, as the + does too. The first edit creates the document with the listed id, the same create the + makes.

**Wide enough images** ([#1371](https://github.com/FRIKKern/barkpark-studio/pull/1371)).

1. Give an image field `"options": {"minWidth": 1200}`, with your own words in `options.minWidthMessage` or the studio's translated default.
2. Pick an 800 px image: a warning shows. At 1200 px there is none.
3. It is always a warning. It never blocks Publish, also on a required field.
4. No known width gives nothing, and an SVG never warns.
5. It works on a field, a field in an object, a field in an array item, and the members of a plain image array (a gallery), where the warning shows on the item.

**Norwegian slugs** ([#1368](https://github.com/FRIKKern/barkpark-studio/pull/1368), [#1369](https://github.com/FRIKKern/barkpark-studio/pull/1369)). Set a slug field's `options.slugify` to `"nb"` and press Generate. æ becomes ae, ø o and å a; other accents are dropped; anything else becomes one hyphen; the slug is cut at `maxLength` with no hyphen at the end. "Bærekraft på Økern" gives `baerekraft-pa-okern`, "Grünerløkka" `grunerlokka` and "£100 i måneden" `100-i-maneden`, and `&` is a break, not "and". `maxLength` is its own option: with none, `"nb"` cuts at 200 ([#1369](https://github.com/FRIKKern/barkpark-studio/pull/1369)). Without `slugify` a slug is the same as before, byte for byte. An unknown name gives that same slug and one console warning. 17 cases are checked against the Norwegian slug code this copies.

**Cross rules per list item** ([#1340](https://github.com/FRIKKern/barkpark-studio/pull/1340)). Yesterday's page showed rules under `cross_validations`. A rule can now run once per item in a list.

1. Give the rule `"each": "meny"`, the path to a list, and optionally a `type` that matches the items' `_type`. A dotted path goes through lists and objects. A leaf reads the item; one with `scope: "document"` reads the document.
2. Break the rule in one item. The problem shows on that item. A closed item row shows a problem mark at its end, before the row menu, for any problem inside it.
3. Past 50 broken items, one more problem on the list says "<title> (N more items)", as Barkpark does.
4. Save. Barkpark's note on the same item does not show a second time.

A rule's message is its title when that is non-empty text, else its name, else "cross-field rule", as on Barkpark. A title given as a per-language map no longer breaks the form while typing ([#1363](https://github.com/FRIKKern/barkpark-studio/pull/1363)). A leaf with `false` in `all`, `any` or `one` is skipped, as Barkpark skips it ([#1373](https://github.com/FRIKKern/barkpark-studio/pull/1373)).

**Saves that cannot succeed stop and say so** ([#1370](https://github.com/FRIKKern/barkpark-studio/pull/1370), [#1376](https://github.com/FRIKKern/barkpark-studio/pull/1376), [#1377](https://github.com/FRIKKern/barkpark-studio/pull/1377)).

- A save Barkpark refuses in a way that cannot go better is final. The footer shows "refused" with Barkpark's words, or "Barkpark refused the change (<status>)". An edit's value stays on screen and in this browser. A refused create makes Duplicate, Translations, a reference's Create and incoming Add item show their toast. No network, server errors, 408, 412, 429 and a 409 on an edit are still sent again.
- A save that keeps meeting a conflict (409 or 412) stops after five rebases (each puts your edits on top of the newest version). Values stay on screen and in this browser. The footer says "Barkpark refused the change (409): someone else keeps saving this document. Your changes are kept here; Retry sends them again." Norwegian too.
- Retry, typing on, or a newer version from the other editor starts it again, with five fresh rebases. Without one of those it sends nothing, however long the tab stays open; on a blur or a pane close too, and the footer stays on "refused" ([#1377](https://github.com/FRIKKern/barkpark-studio/pull/1377)).

**A cleared field stays cleared** ([#1372](https://github.com/FRIKKern/barkpark-studio/pull/1372)). On a type with initial values, empty a prefilled field before the first save: it stays empty. The create sends `null` there, and Barkpark leaves the path empty. Duplicate, from the pane or the bulk dialog, keeps an initial-value path empty where the original left it empty. A type without initial values sends exactly what it sent before.

**Publish selected checks like Publish** ([#1375](https://github.com/FRIKKern/barkpark-studio/pull/1375)). Pick drafts in a list and choose **Publish selected**. Each draft is saved and read whole first, then checked as its own Publish checks it. A draft with an error is held back, and the summary says "N held back by errors — <doc> (<field>: <error>)". Warnings never hold. A draft is also held when it, its type or a document it refers to cannot be read, or when a custom rule throws, rejects or times out. Norwegian too.

**Image and file inputs while the editor loads** ([#1337](https://github.com/FRIKKern/barkpark-studio/pull/1337)). Yesterday's page listed this as not fixed. When the editors' code takes longer than 1.5 s to arrive, the image and file boxes now stay drawn, and the image's Alt field stays in place and takes typing before the code arrives. A press on Upload or Select before the code lands is done when it lands, if the focus is still on that button on the same page; otherwise it is dropped. A file dropped before then is not opened in the tab, and a toast says "The editor is still loading. Drop the file again in a moment." Norwegian too.

**Tooling.** Ten PRs are end-to-end test work, run in 7 parallel groups with a 60 s cap each. Three tests jump the page's clock past a studio timer once it is set, instead of waiting it out, saving 1.0 to 1.2 s each ([#1343](https://github.com/FRIKKern/barkpark-studio/pull/1343)). Two wait for the event itself, a save or the editor's caret, in place of polls and a fixed 200 ms ([#1354](https://github.com/FRIKKern/barkpark-studio/pull/1354), [#1356](https://github.com/FRIKKern/barkpark-studio/pull/1356)). A presence test's clock jump failed on a hosted run and was undone the same morning ([#1342](https://github.com/FRIKKern/barkpark-studio/pull/1342), [#1344](https://github.com/FRIKKern/barkpark-studio/pull/1344)); its replacement also checks that a real user's stream keeps its 20 s quiet window ([#1350](https://github.com/FRIKKern/barkpark-studio/pull/1350)). A unit check fails when a group plans over 49 s, and its message names the two ways out ([#1345](https://github.com/FRIKKern/barkpark-studio/pull/1345), [#1358](https://github.com/FRIKKern/barkpark-studio/pull/1358)). The image Select test prints what the field held when its click is still waiting near the timeout ([#1360](https://github.com/FRIKKern/barkpark-studio/pull/1360), [#1366](https://github.com/FRIKKern/barkpark-studio/pull/1366)).

## Where it is slow or rough

- Not tried in a browser: number radios, whose browser test skips until a fixture field lands and whose Clear step has never run there ([#1346](https://github.com/FRIKKern/barkpark-studio/pull/1346)); fixed documents, whose menus no test renders and whose new row no e2e test covers ([#1367](https://github.com/FRIKKern/barkpark-studio/pull/1367), [#1374](https://github.com/FRIKKern/barkpark-studio/pull/1374)); image min width ([#1371](https://github.com/FRIKKern/barkpark-studio/pull/1371)). Publish selected and the stopped saves had no e2e run ([#1375](https://github.com/FRIKKern/barkpark-studio/pull/1375), [#1376](https://github.com/FRIKKern/barkpark-studio/pull/1376)).
- A held Upload opens the file chooser only if the code lands within the click's activation window, about 5 s in Chrome. Safari drops a press made while the editor loads: press again. Only Chromium was tested ([#1337](https://github.com/FRIKKern/barkpark-studio/pull/1337)).
- Once on a CI run today, the image field's box stayed empty for 15 s. The cause is not known; the test now prints what the field held if it happens again ([#1356](https://github.com/FRIKKern/barkpark-studio/pull/1356), [#1360](https://github.com/FRIKKern/barkpark-studio/pull/1360)).
- `$today` in a list item's initial value is not resolved on either side. With an unknown zone, a type's `$today` field shows empty until Barkpark answers the create ([#1339](https://github.com/FRIKKern/barkpark-studio/pull/1339)).
- A studio without [#1340](https://github.com/FRIKKern/barkpark-studio/pull/1340) skips the usual item rule quietly and can show a wrong error that blocks publishing. Item rules belong in a schema only once both sides are deployed.
- On a Barkpark without its half of the cleared-field change, a cleared field is stored as `null` rather than left out. It still shows empty ([#1372](https://github.com/FRIKKern/barkpark-studio/pull/1372)).
- The slug check, here and in each Publish, says "not taken" when Barkpark refuses its query ([#1375](https://github.com/FRIKKern/barkpark-studio/pull/1375)).
- The 7 test groups plan at most 48.5 s each, yet hosted runs still stopped at the 60 s cap with no failed test ([#1343](https://github.com/FRIKKern/barkpark-studio/pull/1343), [#1356](https://github.com/FRIKKern/barkpark-studio/pull/1356)).
