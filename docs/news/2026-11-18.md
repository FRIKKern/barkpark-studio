# Barkpark Studio · Wednesday 18 November 2026

Twelve pull requests merged. Two let people into a workspace: one to ask for a seat, one for admins to hand them out. Two are about references, one about the table field, and four make Structure pages load sooner and keep sign-in exact. Two speed up the end-to-end tests, and one was the previous day's News ([#1276](https://github.com/FRIKKern/barkpark-studio/pull/1276)).

## What a person can now do

**Ask for a seat** ([#1277](https://github.com/FRIKKern/barkpark-studio/pull/1277)). A seat is membership in a workspace. Signed in with no seat in the workspace the URL names, a person used to see only "Ask a workspace admin". Now they get Sanity's request-access screen:

1. Write an optional message (up to 500 characters) and press **Request access**.
2. The screen says "Access request sent", pending approval, with the date and the message. **Withdraw request** takes it back.
3. While it waits, the screen checks every 15 s and when the window gets focus. An approval opens the workspace without a reload. A decline is shown with its date, and **Ask again** brings the form back.
4. If an invitation to this workspace is waiting, the screen shows **Accept invitation** and **Decline** in place of the form. Accept lets them in at once.

Each refusal reads in plain words and keeps the message, for example "Try again in N min" after too many asks. A workspace that does not exist reads exactly like one that does. Dev and shared sign-in can't ask; they keep the old words. English and Norwegian, light and dark.

**Members, for owners and admins** ([#1278](https://github.com/FRIKKern/barkpark-studio/pull/1278)). A new **Members** screen, from the workspace menu (it shows how many requests wait) and from the Dashboard's Members widget.

1. See who has a seat and their role. Past 8 people a filter appears.
2. See each access request: who asked, their note and when. **Approve** with a role (Member by default), or **Deny**.
3. **Invite** by email with a role. The answer says whether the person was seated now, invited, or reclaimed. Waiting invitations can be withdrawn.
4. **Change a role** or **Remove** a seat. Both ask first and warn when it is your own.

Nobody is offered a role above their own; only an owner sees Owner. An admin can't change or remove an owner. The last owner can't be demoted or removed, and the screen says why. Nobody can approve their own request. Every call goes out with the signed-in person's own token, and other members see no Members entry. With shared sign-in the list is read only.

**Weak references, as Sanity stores them** ([#1285](https://github.com/FRIKKern/barkpark-studio/pull/1285)). In Sanity, a weak reference does not stop its target from being deleted. Before, a pick stored a bare id, so changing a weak reference brought in from Sanity quietly made it strong.

1. Pick in a field marked `weak: true`. It stores `{_type: 'reference', _ref, _weak: true}`.
2. Pick a document that was never published, in any field. The reference is stored weak and marked to be made strong on publish. A strong field still says "Referenced document must be published" until the target is.
3. Press **Publish**. The publish makes such a reference strong in the same step, unless the field is weak. If the publish fails, the draft stays exactly as it was.
4. Open a document whose stored strength the schema disagrees with. Sanity's "Reference strength mismatch" strip shows, with **Convert to weak reference** or **Convert to strong reference**. In the Published view and in a past revision the button is off. Opening a document never rewrites it.

Paste takes the strength of the field it lands in. A strong field that picks a published document still stores the bare id, Barkpark's own shape.

**Search by a reference's id** ([#1287](https://github.com/FRIKKern/barkpark-studio/pull/1287)). Search the exact id of a document, and the documents that refer to it are found whether the reference is stored as a bare id or as Sanity's `{_ref}` object: in a field, a list or an object. Before, only the bare id was found, which missed weak references and Sanity imports.

**Two editors in one table** ([#1280](https://github.com/FRIKKern/barkpark-studio/pull/1280)). When the other editor adds or removes a column while you type, your word now lands in its own column far more often, instead of on the card that holds text the studio cannot place. When its place is unclear it still goes to the card, whole. It never lands one cell to the right. In 464,000 simulated scenes, no word landed in the wrong column; main had 102. On 104,000 of those scenes, the ones that sent text to the card fell from 25,247 to 21,821.

**Structure pages start sooner** ([#1281](https://github.com/FRIKKern/barkpark-studio/pull/1281), [#1284](https://github.com/FRIKKern/barkpark-studio/pull/1284)). The server used to read who you are, then the content model (the schemas and the navigation), then the list and the document, one after another. Now they start side by side:

```
before:  who-am-I → resume mark → content model → list + docs → refs
after:   who-am-I + content model, together
           → resume mark → list + docs, on the model last read here
           → refs, once the fresh model matches (if it changed, the early reads are dropped)
```

The resume mark is where the page's live stream picks up.

- For account and SSO sign-in, a Structure page opened after a minute away reaches its first byte about 70 ms sooner at the median (257 to 188 ms) and 140 ms at p90, measured on one Mac. Warm loads are unchanged.
- A document page loaded more than 5 s after the last one reads its list and document early. In two test runs, the document pages that had to read the content model reached their first byte in 362 and 383 ms at the median, from 487 ms.
- Reads start early only for shared sign-in or a seated editor whose token Barkpark has not refused. Nothing read early reaches the page unless the who-am-I answer lets this person in.

**Sign-in, kept exact** ([#1283](https://github.com/FRIKKern/barkpark-studio/pull/1283), [#1289](https://github.com/FRIKKern/barkpark-studio/pull/1289)). An empty token is never remembered as refused; only a token that names someone is. A request signs out at most once. Both rules, and the check that decides whether the early reads may start, now have unit tests that fail when the rule is broken.

## Where it is slow or rough

- None of today's screens was compared side by side with a running Sanity Studio. Members has no studio screen to compare with: Sanity keeps members on its own website ([#1278](https://github.com/FRIKKern/barkpark-studio/pull/1278)). Request access and weak references were built from Sanity's source ([#1277](https://github.com/FRIKKern/barkpark-studio/pull/1277), [#1285](https://github.com/FRIKKern/barkpark-studio/pull/1285)).
- No access request, approval, invitation or role change was written on a real Barkpark: seats are real, so every write ran against a stand-in that is on only in tests. No real account or SSO session was tried ([#1277](https://github.com/FRIKKern/barkpark-studio/pull/1277), [#1278](https://github.com/FRIKKern/barkpark-studio/pull/1278), [#1281](https://github.com/FRIKKern/barkpark-studio/pull/1281)).
- Both table browser tests skip in CI, whose datasets lack the table field; the new one has run only as scene scripts. The browser runs came before the review's last fix ([#1280](https://github.com/FRIKKern/barkpark-studio/pull/1280)).
- A publish that Barkpark runs itself, a scheduled one or a content release, leaves a waiting reference weak ([#1285](https://github.com/FRIKKern/barkpark-studio/pull/1285)).
- The end-to-end tests run in 7 parallel jobs (shards), each cut off at 60 s. Over main's last 5 runs, its shards hit that cap 9 times in 35, with every test passing. [#1279](https://github.com/FRIKKern/barkpark-studio/pull/1279) cut the recorded test time from 352.6 to 330.2 s, which it puts at about 1 cap in 35. [#1282](https://github.com/FRIKKern/barkpark-studio/pull/1282) cut the upload-cancel test from 7.9 to 5.5 s; both its runs were green. The 42 s goal for the slowest shard is not met: the same files still swing about 10 s from run to run.

## Across the projects

Barkpark is the core: the studio asks it for everything. Request access and Members call the access requests Barkpark added the day before ([FRIKKern/barkpark#26848](https://github.com/FRIKKern/barkpark/pull/26848)). [#1285](https://github.com/FRIKKern/barkpark-studio/pull/1285) named one Barkpark gap: deleting a document a weak reference points at was still refused when the reference sat in a schema reference field. Barkpark merged a fix late the same day: with it, such a delete succeeds and leaves the weak reference dangling, as in Sanity, while a strong reference still blocks ([FRIKKern/barkpark#27251](https://github.com/FRIKKern/barkpark/pull/27251)). On the roadmap, Request access, Members and weak references are built; the owner has signed off none of them yet.
